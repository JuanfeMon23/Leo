# Catálogo de reusables — núcleo backend de Leo (`backend/app/core/`)

Única fuente de los elementos reusables del backend (schemas genéricos, dependencias, excepciones, utilidades criptográficas, helpers de tests): firma y quién los usa. Formato y regla de ubicación: patrón `reusable-catalog` de Ying. Criterios propios: skill `backend-reusable-core`.

| Elemento | Ubicación | Firma / uso | Usado por |
|---|---|---|---|
| `get_settings()` / `Settings` | `core/config.py` | Solo infraestructura desde `.env` (`DATABASE_URL`, `LEO_FRONTEND_URL`, `LEO_PUBLIC_URL`, `LEO_COOKIE_SECURE`, `LEO_RATE_LIMIT_BACKEND`, `LEO_TRUSTED_PROXIES`). Las políticas viven en `settings` (ver `runtime_settings`); `LegacyPolicyEnv.initial_values()` lee las variables antiguas solo como valor inicial. | todos |
| `runtime_settings`: `LEO_SETTINGS` (registro), `store`, `get(key)`, `get_many(*keys)`, `password_policy()`, `sync_on_startup()` | `core/runtime_settings.py` | Ajustes editables (módulo compartido `leo_sdk.settings_store`): `await runtime_settings.get("auth.idle_timeout_minutes")` por petición (caché ~10 s, invalidada al editar; fallback al default si la BD falla). Para añadir una política: declarar su `SettingDef` aquí (se inserta sola al arrancar). Tests: `testkit.set_setting(session, key, value)`. | auth, users, audit, pagination, settings |
| `settings_router` | `modules/settings/router.py` | `/api/v1/settings` (GET lista agrupada, GET `{key}/history`, PUT `{key}`) con permisos `leo.settings.view/edit/edit-security` y auditoría `leo.settings.update`. | `main.py` |
| `clock.now()` | `core/clock.py` | Reloj UTC de la app; los tests lo adelantan con `monkeypatch.setattr(clock, "now", ...)`. Usar `from app.core import clock`. | auth, users, dpop, rate_limit |
| `get_session` / `SessionDep` | `core/database.py` | Una `AsyncSession` por request. | todos los routers |
| `AppError` y subclases (`BadRequestError`, `UnauthorizedError(www_authenticate=)`, `ForbiddenError`, `NotFoundError`/`not_found(subject, id)`, `ConflictError`, `DuplicateValueError(entity, field, field_label, value)`, `ValidationAppError`, `TooManyRequestsError(msg, retry_after)`) | `core/exceptions.py` | Los controllers lanzan estas (nunca `HTTPException`); `code=` opcional por instancia. | todos |
| `register_exception_handlers(app)` | `core/exceptions.py` | Formato único `{code, message, details}` en español: validación (422 `validation_error`, `details: [{field, message}]`), SQLSTATE 23505→409 `duplicate`, 23503→422 `invalid_reference`, 23514→422 `validation_error`, `LEO01`→409 `append_only`, resto→500 `internal_error` sin detalles. | `main.py` |
| `ErrorResponse`, `Page[T]`, `error_responses(*statuses)`, `AUTH_ERRORS` | `core/schemas.py` | Error uniforme, página genérica y `responses=` documentados en OpenAPI. | todos los routers |
| `PaginationDep` (`page_size` máx. = ajuste `pagination.max_page_size`), `SearchQuery`, `ActiveQuery`, `search(stmt, q, *cols)`, `only_active(stmt, active, col)`, `paginate(session, stmt, pagination, ReadModel, *order_by) -> Page`, `get_or_404(session, Model, id, subject)` | `core/pagination.py` | Listados `?page=&page_size=&q=&active=`; `get_or_404` recarga la fila (`populate_existing`). | applications, users, roles, auth, audit |
| `Slug`, `ActionTag`, `HttpUrlStr`, `text(n)`, `optional_text(n)`, `UpdateModel` (`immutable_fields`, `non_nullable_fields`) | `core/validators.py` | Tipos Pydantic con los patrones de `core/db/checks.py`; `UpdateModel` = base de los PATCH: rechaza campos extra, inmutables (slug/verb) y nulos en columnas obligatorias. | applications, roles, users, audit |
| `new_opaque_token() -> OpaqueToken(value, hash)`, `sha256_hex`, `sha256_b64url`, `constant_time_equals`, `pkce_s256_matches`, `b64url_encode/decode` | `core/crypto.py` | Tokens de 256 bits; a la BD solo `hash`. | auth, applications |
| `verify_dpop_proof(proof, htm, htu, now, cache, access_token=None) -> DpopProof(jkt, ...)`, `DpopError(reason)`, `JtiReplayCache`, `replay_cache`, `jwk_thumbprint(jwk)` | `core/dpop.py` | RFC 9449 ES256 sobre `cryptography`; anti-replay en memoria (pendiente multi-instancia). | auth (`dependencies.verify_request_dpop`) |
| `Principal`, `CurrentPrincipal`, `require_action(tag)`, `require_actor(tag) -> Actor`, `configure_authz(resolver, on_denied)` | `core/authz.py` | Protege la API de Leo con `leo.*`; 403 `forbidden` + evento `denied` persistido. Al declararse rechaza (ValueError) tags no registrados en `core/db/seeds/catalog.py` y tags de evento (descripción "Evento:"). El resolvedor (auth) y el hook (audit) se conectan en `main.py`. | todos los routers admin |
| `ClientApp`, `AuthenticatedClient`, `configure_client_auth(authenticator)`, `invalid_client()` | `core/client_auth.py` | Client credentials por HTTP Basic (`client_id:client_secret`); 401 `invalid_client`. | auth (`/token` incl. `client_credentials`, `/introspect`, `/revoke`), applications (catálogo), audit (ingesta) |
| `AuditEntry`, `Actor.entry(tag, **campos)`, `diff(before, after)`, `snapshot(entity, fields)`, `is_sensitive(name)`, `json_safe(v)` | `core/audit.py` | Piezas puras del cliente de auditoría; descartan password/secret/token/hash/jkt. La escritura es `audit.record_event` / `record_change` / `record_and_commit` (interfaz pública del módulo `audit`). | todos los controllers |
| `RequestMeta`, `Meta`, `request_meta(request)`, `RequestIdMiddleware` | `core/request_meta.py` | ip (validada), user-agent (≤512) y `X-Request-ID` para sesiones y auditoría. | auth, audit, applications, `main.py` |
| `SlidingWindowLimiter(bucket=, store=)` / `make_limiter(bucket)` | `core/rate_limit.py` | `retry_after(key, at, limit=, window_seconds=)`, `hit(key, at, window_seconds=)`, `check_and_hit(key, at, limit=, window_seconds=)`, `reset()`; el límite y la ventana se pasan en cada llamada (ajustes `rate_limit.*`, ver `auth.rate_rule`/`failure_rule`); almacén `memory` o `postgres`. | auth (login, emisión de tokens de servicio: `service_token_limiter()`), users (`provision_limiter()`) |
| `hash_password`, `verify_password`, `needs_rehash`, `burn_verification_time`, `password_weaknesses(pw, policy=)`, `PasswordPolicy` | `core/security/passwords.py` | argon2id; política compartida con la semilla. `PasswordPolicy` (de `password.*`) sube el mínimo o quita clases, pero la longitud queda entre 12 y 128 (piso/techo de código). | users, semilla |
| `SelfManager`, `auth.delegated_update_profile/delegated_change_password`, `users.self_service_reason(via, detail)` | `modules/auth/controller.py`, `modules/users/controller.py` | Logica unica de autogestion (perfil/contrasena) para la cookie SSO y para el delegado de servicio (`/users/service/delegated/*`, tag `leo.users.delegated-self-manage`, rol `leo-self-service-delegate`); `via=servicio:<client_id>` en `reason` de auditoria; limitadores `delegated_by_app` / `delegated_by_user` en `login_limiters()` (ajustes `rate_limit.delegated_*_per_window`, 120). | auth, users |
| Helpers de tests: `DpopKey` (`core/tests/dpop_keys.py`); `Browser`, `make_user`, `make_client_app`, `make_role`, `make_action(session, app, tag, name=None)` (nombre por defecto = `derived_action_name(verb)`), `grant`, `grant_service_access(session, caller_app, role)` (concesión entre apps), `pkce_pair`, `leo_app`, `leo_admin_role` (`app/testkit.py`); fixtures `session`, `make_browser`, `browser`, `admin`, `client`, `login_as` (`app/conftest.py`) | `core/tests/`, `app/` | BD `leo_test` con rollback por test y semilla `leo` aplicada; navegadores con llave DPoP propia. | tests de núcleo y módulos |
